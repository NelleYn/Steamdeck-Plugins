# DeckPiP and the Decky Plugin Store

## Short answer

**DeckPiP cannot be submitted to the official Decky Plugin Store as
it stands today.** Two policy blockers and several requirements
follow.

## Hard blockers

### 1. AI-generated code policy

The
[`plugin_addition.md` PR template](https://github.com/SteamDeckHomebrew/decky-plugin-database/blob/main/.github/PULL_REQUEST_TEMPLATE/plugin_addition.md)
includes the checkbox:

> I confirm that the **majority** of this plugin's code was not
> generated by generative AI.

This whole plugin was written via AI pair programming. The reviewer
team specifically calls this out and rejects PRs they suspect are
AI-authored.

The store will not accept DeckPiP unless the codebase is rewritten by
a human author, or the policy changes (it has not as of May 2026).

### 2. Custom binary dependencies on pacman

Decky's preferred shape for a plugin's runtime is **self-contained**:
either pure Python on the backend, or **statically linked binaries
shipped inside the plugin directory**. The store explicitly
discourages plugins that ask the user to run `pacman -S …` to install
system packages, because it breaks SteamOS's immutable-root model and
survives badly across OS updates.

DeckPiP today depends on `tigervnc`, `python-websockify`, `novnc`,
`xterm`, `wmctrl`, `xdotool`, `gst-plugin-pipewire` and
`gst-plugins-good`, all installed via `defaults/install.sh`. To pass
store review, every one of those would need to be bundled as a
portable binary tarball under `DECKY_PLUGIN_RUNTIME_DIR`. That's a
realistic engineering effort (the
[`tigervnc-static`](https://github.com/TigerVNC/tigervnc) project
already produces standalone builds, and noVNC is a static folder of
HTML/JS), but it has not been done.

## Soft requirements we already meet

- **`plugin.json`** — schema matches the template (`name`, `author`,
  `flags`, `api_version: 1`, `publish.{tags,description,image}`). ✅
- **BSD-3-Clause license** declared in `package.json` and `LICENSE`.
  ✅
- **Backend Python uses the `decky` module** the loader provides. ✅
- **Frontend builds with the upstream `@decky/rollup` preset** — no
  weird bundler hacks. ✅
- **No telemetry, no phone-home** beyond the optional self-update
  check against the user's own GitHub PAT. ✅
- **API version 1** is the current accepted value. ✅
- **No paid features, no required logins** — also clean. ✅

## What "submission" would look like once blockers are cleared

For reference; this is the process the maintainers documented:

1. Make the repository public (Decky bot needs to read it, and
   testers need to pull it).
2. Tag a release on GitHub. Attach `DeckPiP.zip` (the same shape our
   CI already produces under `build-pack/`).
3. Fork `SteamDeckHomebrew/decky-plugin-database`.
4. Add DeckPiP as a git submodule under `plugins/DeckPiP`.
5. Open a PR using the **plugin_addition** template; fill in:
   - Original-author confirmation.
   - License compliance.
   - **AI policy** (this is the blocker today).
   - Backend type (we'd be "custom backend").
   - Tested-on-Stable / Tested-on-Beta channels.
6. Wait for two community testers to pick up the PR and post test
   reports.
7. Reviewer team merges, store updates.

## Until then: how users install DeckPiP

DeckPiP is distributed exclusively via this repository:

- **For maintainers / developers:** clone + `bash setup.sh`.
- **For non-developers:** ask the maintainer for a `DeckPiP.zip`
  built by CI and install via Decky's
  *Developer mode → Install from URL* against any hostable direct
  link (releases page, gist, file share).

When the repository becomes public, the GitHub Release URL
(`.../releases/download/dev/DeckPiP.zip`) becomes usable as the
direct link Decky expects.

## Honest recommendation

Use DeckPiP as a personal / friends-circle plugin distributed
directly from GitHub. Submitting to the official store would require:

1. A complete human rewrite, OR a published policy change.
2. Vendoring all runtime binaries.
3. Tested validation on both Stable and Beta SteamOS channels.

(2) and (3) are tractable. (1) is the gating issue.
